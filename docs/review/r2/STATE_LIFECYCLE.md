# R2 state lifecycle

1. Start a trajectory with the sole registered checkpoint (Stage II only), fresh Adam and empty banks. There are no domain-boundary notifications, resets or recovery operations.
2. Increment global visit. Snapshot each ready bank before any current-image computation. Each snapshot is a detached clone and its version must be less than the current visit.
3. Run six weak predictions. The first original-view seg_head input is detached and retained only for this current visit. R1 aligns weak probability grids with the original 32x32 grid. Region masks and reliability are based on this existing weak computation.
4. Stage at most 32 reliable unit vectors per region from the original features. These staged vectors have not entered memory. The loss uses all hard-partition tokens, regardless of memory reliability sampling. Token c*1024+u always pairs original and strong position u, including shuffled banks.
5. Run the existing strong prediction. Compute original C loss plus 0.05 times the specified extra loss. Only strong features carry gradients through the extra term; f0, mean and basis are detached. No extra forward, backward or autograd.grad is used for diagnostics.
6. Perform one backward and one Adam update, then the existing post-update final prediction. The returned prediction is fixed before target mask decoding/evaluation.
7. Only after that final prediction merge the staged original, pre-update vectors. D calls the original cumulative bank. E/DE/F/DE-S decay W and M2 by rho and Q by rho squared on every global visit, even with no contribution, then merge any new weight-one tokens. Never merge post-update features.
8. Refresh only on a contributing image when raw support reaches 16 images/128 tokens and the contributing-image count is a multiple of 16. Covariance is CPU float64, symmetrized M2/(W-Q/W); finite eigenvalues above 1e-10 determine actual rank up to 8. Snapshot center/basis/version change only at refresh. Empty visits decay statistics without refreshing or expiring the old snapshot. Rank zero is inactive; numerical/eigh failure propagates as failure.
9. Clear pending f0/fs/views/vectors/snapshots in finally, including on errors. Host scalar diagnostics are also cleared after copying into its return record. Algorithm state retains only model/Adam, original augmentation RNG and sufficient statistics/basis. No raw observations, input pixels, masks, domain identity or feature history survive in the algorithm state.
10. The evaluator subsequently reads the current mask using the unchanged verified-byte R1 path. JSONL contains scalar metrics/audits and private identities, not feature tensors. Public aggregates omit per-content identities. Finish removes hooks. A new trajectory gets new banks.

Per bank: mean[32], M2[32,32], raw_n, contributing images, last visit, merges, eig calls, optional snapshot center[32], U[32,k], eigenvalues[k], version. Weighted banks additionally keep scalar W, Q, rho and optional scalar projector change. At rank 8, tensor storage is 10,816 bytes per bank, 43,264 bytes for four banks; scalar/object overhead is not included in tensor byte counts. Persistent PCA state remains far below 1 MiB. Current-visit staging is transient and separate from that count.

F pays the same shadow sufficient-statistic/eigh costs and observes the same readiness rules as DE; loss direction is independent of U. Raw support and effective weights are separate fields. Global visit and contributing-image count are not interchangeable.

R2 imports R1's reviewed process-group cleanup and atomic publisher. `R2_EXPERIMENT_REPORT.md` is an alias through the same atomic `current` pointer to the publisher's legacy internal `R1_EXPERIMENT_REPORT.md` filename. Its content and result status are R2. Invalidating current results makes both aliases unavailable. A failed recomputation cannot leave a valid success pointer.
