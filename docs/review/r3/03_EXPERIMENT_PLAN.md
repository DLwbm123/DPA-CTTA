# R3 一次性实验计划

## 1. 本轮是什么、不是什​​么

这是一次冻结的五框架筛选：不组合框架，不做超参数网格，不按中间分数决定其他框架是否运行。结果只支持本配方、同checkpoint、有限顺序下的开发判断；不是独立患者验证、源知识遗忘证明或最终TMI实验。

阶段I实现并公开固定提交；外部review检查代码是否实现了假设。通过后用户授权设备与后台方式，再运行一个有限队列。没有效果准入gate；真实工程错误、未授权设备、超资源限制才停止。

## 2. 同批矩阵

| 家族 | 主候选 | 控制 | 主要问题 |
|---|---|---|---|
| 共用基线 | C、RP | — | 同批C与原REGION，不以旧均值替代新配对 |

共17臂：2基线＋5主候选＋10控制。不能把每个控制都算成一个原创框架。各主候选同时比较C、RP及两组直接控制。

本批新增了M_IDPOST，专门防止把“存储更新后特征”的效果误归给“迁移历史坐标”；它是必要的匹配控制，而非新的主模块。

## 3. 数据与流

### 3.1 基础资产

保持1,951个已登记Fundus内容组、现有域内顺序、子集标记及读取器。主要子集remaining_dev为1,695组；legacy_dev/p1_extension_dev/all_dev完整附表，但不更换主终点。

基础registration预期digest：

`8afb0a9ea4e5fe1701bd89a04778de1b2ef0fac70e7aa8ec62fe288f071ffeaf`

该值来自既有交付，本包没有访问NAS重新核验；实际运行器核对真实私有登记。不得重建split、补患者登记或删除UNKNOWN组来启动新一轮。

### 3.2 四个既有主域序

| stream | 域块顺序 |
|---|---|
| 0 | REFUGE → ORIGA → REFUGE_Valid → Drishti_GS |
| 1 | Drishti_GS → REFUGE_Valid → ORIGA → REFUGE |
| 2 | ORIGA → Drishti_GS → REFUGE → REFUGE_Valid |
| 3 | REFUGE_Valid → REFUGE → Drishti_GS → ORIGA |

四序均为完整单遍，各方法各序独立初始化。域标签用于loader排程和评分汇总，不提供给host/路由器。每个内容在一条轨迹内只访问一次。

### 3.3 一条预先固定的块交错回访流（stream4）

为了让状态检索路线真正遇到环境回访，本批同时为**全部17臂**运行一个secondary流。不是看主结果后再追加。

按每域原顺序切成最多64个内容的连续块。第r轮将基础域顺序 `[REFUGE,ORIGA,REFUGE_Valid,Drishti_GS]` 左移 `r mod 4` 位，依此从仍有内容的域取下一块；耗尽域跳过，直到1,951个内容全部出现。例如前两轮域顺序为`A B C D`、`B C D A`。

这里回访的是**环境模式**，每个内容ID在该流内仍然只出现一次；不重复旧图，不用测试时replay缓存。所有方法接收相同流，并且只收到当前图。块大小64、轮换规则固定，不搜索最有利于S的切换频率。

由现有登记元数据派生新stream digest，基础registration不变；不预读任何像素或mask。`reference.recurring_stream()`给出确定性参考。

该流是另一种开发压力测试，不是新患者数据，也不是直接旧任务保留矩阵。**它与四主序分开汇总，不能将5序合并成一个平均值来改变排名。** S若只在该流有效，只能收窄到回访环境复用主张，不能宣称原四序统一提升。

## 4. 正式预算

每流1,951个图，17臂×5流=85条完整轨迹。

| 部分 | 轨迹 | 正式评分／Adam／loss backward | 网络forward |
|---|---:|---:|---:|
| C、RP | 10 | 19,510 | 156,080 |
| T三臂 | 15 | 29,265 | 263,385 |
| U三臂 | 15 | 29,265 | 234,120 |
| S三臂 | 15 | 29,265 | 263,385 |
| M三臂 | 15 | 29,265 | 234,120 |
| G三臂 | 15 | 29,265 | 234,120 |
| **总计** | **85** | **165,835** | **1,385,210** |

其中四序主比较为68轨迹／132,668条评分，回访secondary为17轨迹／33,167条评分。实际不同内容仍只有1,951组。

U的Jacobian VJP额外每图最多8次，合计上限 **234,120**。loss backward仍为165,835，但总autograd reverse调用可能达到399,955；不把VJP忽略。ready前或无有效probe会低于上限，报告实际数，不人为补零反向凑数。

其他额外成本：T的Cholesky/密度，S的状态装载，M的32×32 SVD，G的1984边×32次图迭代，均分别计时。没有新增source/DD/元训练。相同更新次数不等于相同FLOPs或时间。

这是R2正式更新数量的4.25倍。资源授权必须明确覆盖此完整矩阵，不能让用户误以为只跑5×1,951次。

## 5. GPU smoke：每设备只做一次，不按效果筛选

每块实际授权GPU：17臂各一个cold step和一个人为构造ready-state step（程序化图像、程序化memory）；再对旧C和旧RP各做两步参考。合计：

- 38次Adam、38次loss backward；
- 316次网络forward；
- 最多24次Jacobian VJP（U三臂的ready各最多8）；
- smoke不进入正式效果表。

ready fixtures只在test/smoke入口可用，正式入口必须空目标memory初始化；不能把程序化stat或测试状态写入正式run。新context能创建和装载、teacher能修正、图有边、U位移确实改变、M快照真的迁移，在程序化输入下验证机械路径即可，不要求Dice有意义。

机械smoke通过后不回到GPT等待效果批准，直接进入已授权的完整有限队列。真实smoke错误则停止，不调学习率以通过。

若用物理GPU6和7两卡：含smoke总计165,911次Adam／loss backward、1,385,842次network forward、最多234,168次Jacobian VJP。只读模型加载、CPU预处理不是forward。

## 6. 运行组织与资源权限

- GPU6/7仅是沿用偏好，当前并未授权；最多支持3个worker，实际列表由用户在阶段II指定。每卡最多一个本作业worker，不终止他人程序。
- `worker=(arm_index+stream_id)%num_workers`固定轮换，四主序中不让一个方法永久绑定某一GPU。单条轨迹不中途换卡，不拆散样本顺序。
- 先级只决定开发及固定任务表的位置；不依据观测分数决定优先继续哪一个方法。主候选及控制全跑，失败收尾例外。
- 一次有限队列内，trajectory上限6h，总active-worker上限160h，墙钟上限96h，新私有输出上限6GiB。这些是停止上限，不是预计完成时间，不保证一定消耗到此上限。
- 运行前将实际权限、code SHA、science SHA、stream digest、设备型号和真实计数绑定在新run receipt。science文件不因“审批通过”改写。
- 不默认沿用R1/R2旧GPU/后台授权。没有收到后台权限就不要启动持久会话。

已完成轨迹可以在经授权的工程续跑中复用，但不自动retry；中断前缀保留、排除主表，重跑完整失败轨迹必须先明确授权。日志失败不能阻断进程清理。不得隐藏额外物理成本或把多次工程重试计作独立seed。

## 7. 主评价与配对

所有方法同批重新执行C和RP。旧C/RP/R2_E只作为兼容性、历史参考附表，不承担本批唯一主对照，也不作为当前轨迹状态初始化。

主结果：每图OD/OC均值→域内均值→四域等权→四主序描述性等权。OD/OC也分别报告。保持现有Dice空/满规则、threshold=0.5、ASSD grid与共同有效cohort；undefined ASSD不能填0。

每个主候选与C/RP/直接控制计算：每序及四序均值、各域OD/OC、配对中位数、正零负比例、最差ceil(0.1n)均值、最差单图、共同有效ASSD及分母。REFUGE_Valid OC单列；Drishti_GS的37组与25%域权重明确披露。不得事后按域名选择最优臂拼成统一结果。

secondary流使用相同单流域等权指标，单列所有17臂；可按同域第几次块返回观察性能、slot复用和装载情况，但算法不得读取这个位置标签。回访流不是额外患者重复。

单seed保留20260907；多序共享内容，不制造患者层面显著性。无需在本筛选批次做不正确的像素bootstrap。未使用独立数据，任何正结果仍属开发证据。

## 8. 附带机制信息，不新增诊断轮

正常forward中获得的标量即可：

- T：pair-ready比例、支持比例、logit修正幅度、前景/背景密度差分布；evaluator可在输出固定后算q/q*的纠错／误纠正计数。
- U：有效probe行数、实际VJP数、raw/实际Delta范数与角度、线性probe变化、post原图的实际probe变化。
- S：创建/切换/容量overflow/复用次数、每slot Adam步数、路由距离与旧阈值、bank ready及内存。记录缺乏激活而非自动改threshold。
- M：正确或打乱配对数、identity回退次数、Q正交误差、||Q-I||、前后拟合残差、frame/eigen版本，不保存Q全矩阵到逐图公共报告。
- G：边权分布、迭代前后能量、teacher包含违反数、teacher修正比例、原始最终预测违反比例（不强制修正）；solver耗时。

只将这些信息用于解释，不能反馈调参或停止落后方法。CPU汇总只重算可从保存标量重算的量；不能声称重建未保存的feature covariance、Jacobian或ASSD几何。
