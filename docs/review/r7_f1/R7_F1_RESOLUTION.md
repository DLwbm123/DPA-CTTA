# R7-F1 shared inference identity repair

Scope: Stage I procedural CPU, external review AWAITING_REREVIEW. The reviewed implementation is `82aca2080bb80c019b0d39b4c95d21a6ba2cff3d`; historical publication is `7f129b484a5ab2b0af3efdf2ccea0eee1228969c`. Their reports and logs are retained.

The prior method-only binding allowed a different frozen segmenter to reuse a trained method or saved state. The new shared context binds the actual frozen backbone, projection, policies, method assets and source/design provenance. Both the real fresh loader and state restore reject incompatible contexts before any model forward. C0 has a full environment context. Old method-only bindings and unversioned state packets are explicitly unsupported, never silently upgraded.

`prepare_tensors` captures the frozen environment before source preparation and requires every output to retain it. Each of the six independent FULL/STATIC outputs contains a versioned artifact, copied method weights and a complete context. The fresh loader requires this trusted saved context; it never makes its expected identity from the candidate segmenter. `prepared_artifact` also provides the explicit procedural C0 release path. A deployment ablation requires `deployment_context(trusted_prepared_context, ablation)`, which derives a new context solely from trusted preparation metadata and the permitted fixed ablation. The fresh loader does not silently rewrite expected ablations.

`OnlineHost` can anchor a direct in-memory procedural session without an artifact. This is not source authentication. Production fresh reconstruction uses `inference_from_tensors` with independently trusted preparation metadata. Hashes detect compatibility/integrity, not signatures or arbitrary caller authenticity.

No A/B/C algorithm, loss, hyperparameter, source budget, science byte, matrix, tolerance, gate, old C or historical result was changed. The old 47 checks remain; 12 context tests were added. Their positive/negative cases use all A/B/C/C0 loaders, state packets, projection/backbone changes, policy/BN configuration, method assets, static/group/ablation, legacy packets, and in-place mutations. One uses two independent random full ResUNets and checks exact next-output equality and changed-encoder rejection. Another runs real `prepare_tensors` packaging/control flow with explicitly mocked expensive training phases: its 1000/256 markers are mock values, not executed steps. Existing full-network micro-training, calibration, gradient, label isolation and old-C checks remain the source of that coverage.

Tensor bytes are hashed at construction, artifact save, and state save/load boundaries. The per-visit guard examines local tensor identity/version/shape/dtype/trainability/device and policy/module metadata, with no full-model byte scan and no extra model forward/backward/optimizer/VJP. Object IDs are used only for that in-process mutation guard, never portable binding. Deliberate `.data` or raw storage writes can bypass version counters and are unsupported between visits; boundary rehashes still catch changed content. This ceiling is explicit, not a claim of protection from arbitrary in-process code injection.

The actual source checkpoint, manifests/splits and trained file bindings remain PENDING/null. Random effective-state digests are not checkpoint-file digests. This remains a CPU tensor backend; GPU migration, real source IO and finite execution wrappers are later separately authorized work. No GPU query, real image/mask/checkpoint access or real execution was performed.
