## Data and identity flow

The metadata-only registry validates the exact original target registration, source domain, named content/eye/patient grouping evidence, duplicate identities, image overlap, minimum32/4/4 groups and disjoint folds. It never turns a filename into a patient ID. `freeze` uses the existing R7 split function, binding the normalized manifest payload and explicit representatives before pixels. For groups containing multiple registered rows the smallest registered sample_id is an explicit deterministic representative, not an additional independent patient. Same-image hashes cannot cross groups. CONTENT/EYE use requires the explicit PATIENT_DEPENDENCE_UNKNOWN label. Patient overlap is unidentifiable where linkage is absent; content non-overlap does not prove subject non-overlap.

`preflight` first rejects missing/disabled/wrong scope authority, then checks the clean final Git SHA, separate SOURCE_PREP external review, immutable four science bytes, independent manifest/split/target/config hashes, source checkpoint registration, resources tied to the new user receipt and fresh disjoint private output. Stage I PASS and a BOUND string alone do not unlock anything. TARGET scopes never dispatch here. Defaults and authorization template remain disabled, device IDs and resource authorization null. Private provenance is caller-supplied and externally reviewed; hashes are not signatures or authentication against malicious in-process callers.

Reader paths are explicitly rooted in RIM_ONE_r3, reject traversal/symlinks/hardlinks, and verify bounded ordinary-file bytes before feeding the same BytesIO to the existing fundus RGB/mask decoder. RGB uses existing bicubic resize to512; masks use nearest resize with OD<255 and OC=0. Checkpoint bytes are checked separately and loaded CPU/weights_only with strict original ResUNet state matching. The old checkpoint is not retrained. Metadata input, raw byte reads, pixel decodes, checkpoint deserialization, effective tensor hashing and trained artifact hashing are distinct operations/counters. Read attempts/bytes and decode attempts remain recorded on failure. Used source assets and metadata are verified read-only afterward; a second error never replaces the first training error. Outputs are new ordinary files outside source/code/metadata; no historical links, results, gates or old recompute/publish operations are touched.

## Device, algorithm and budget

This implementation deliberately qualifies **CPU only**. Backbone/FiLM pixels and new neural modules use float32; the existing bases, latent states and small solves use float64; CPU photometric simulation and labels remain CPU. The existing tensor backend performs the unchanged .float/.double transitions, preserving query gradients through FiLM. There is no implicit GPU migration: CUDA/device IDs or a different dtype policy fail before asset decoding or device discovery. GPU support, migration, GPU smoke and GPU numeric checks are NOT_RUN, not inferred from CPU tests.

The shared tensor pipeline is reused. Only optional phase notifications were added, plus the C calibration callback before its existing constant-variance computation. They add no model calls or scientific choices. Source oracle fit/cal/val, shared basis, A basis/VJP, scaler, each of six initialize/fit/cal/constant-R/package/val phases and independent oracle-query diagnostics have separate elapsed CPU/wall, numerical counters and hash costs. No ranks, steps, supports, roles, seeds, losses or tolerances change. FULL/STATIC remain separately initialized and trained at1000 fit +256 calibration steps each. Per-phase physical counts are checked exactly; forward caps and finite wall checks run before each model forward. Shortened/missing phases fail rather than being accepted as completion. Validation is the existing64 fixed episodes per model, not best-checkpoint selection.

The single child has a parent wall/output cap, neutral command line, no smoke or target dispatch, and no retry. The parent reuses historical `stop_owned` without editing it; a narrow macOS EPERM-after-exit fallback additionally requires a reaped child and an independent ps proof that its PGID is absent. Cleanup failures have separate evidence; they never replace an earlier timeout/worker error. A child exit0 alone is insufficient: the parent also requires the complete source execution record and unchanged source after-check. Output byte caps reserve terminal error space. No background source task is started by this preparation work.

## Trusted deployment artifacts

Each model retains the reviewed complete inference context. The runner checks the actual fresh loader before release, saves weights and context separately, and emits an independent inventory with trained-file SHA256, context-file SHA256 and composite context SHA256. `load_artifact` uses the trusted saved inventory/context and verifies the candidate through the existing loader; it does not generate expected identity from the candidate. A trained-file hash remains external to its own context to avoid a self-referential hash. Checkpoint file hash, effective frozen tensor hash, method digest, context hash and trained-file hash are separate fields. Source images, masks and oracle support tensors are not included in deployment packages. Validation/projection/basis/oracle-query diagnostics are private by default.
