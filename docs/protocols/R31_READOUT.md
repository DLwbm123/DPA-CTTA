# R31: final-classifier adaptation with persistent consistency learning

## Evidence and hypothesis
R30 completed all 54 jobs: C_CONT exceeded per-image episodic C by 3.22554 Dice percentage points on SEARCH, while parameter/optimizer resets all lost to ANCHOR. Local H64 oracle strength gains were only 0.00901 pp. Stop these strength/reset sweeps. The rank-4 ANCHOR increment over C is small and order-dependent. A different, limited hypothesis is that the fixed source classifier constrains class-specific channel recombination. BN affine updates can rescale shared channels but do not freely alter each output class's channel weights. This is a testable hypothesis, not evidence that unfreezing must help or a novelty claim.

## Frozen algorithm and matrix
Three arms C_CONT, ANCHOR, C_HEAD; seeds 20260907,17011,29009; two existing orders; 18 full streams of 1951 arrivals. All arms start from identical registered source weights and retain parameters and Adam across arrivals. C_HEAD alone enables the existing seg_head.weight (2,32,1,1) and bias (2), 66 scalars, at fixed Adam LR 1e-5. Existing BN affine LR remains 1e-4. No adapter is added to C_HEAD. ANCHOR remains the unchanged R24 reference. Same source architecture, augmentation RNG policy, six weak views, one strong-view consistency backward and one Adam step, then original-image readout. No LR sweep, entropy objective, reset, reward, RL, ensemble, source training, new data or model. Existing historical BN-only contracts remain valid for C_CONT and ANCHOR; this protocol explicitly permits only the 66 registered extra scalars in C_HEAD. All other non-BN parameters remain frozen.

All 18 streams rerun in this round for paired baselines and cost accounting. A smaller six-stream candidate-only run could reuse R30 masks, but is not used here because within-round rerun references provide direct implementation controls.

Each of three A100 GPUs profiles eight arrivals per arm; C_CONT/ANCHOR also replay their exact reference logits and state. Complete ANCHOR trajectories verify registered R28 probe masks. Mechanical checks precede profiles and all profiles must pass before formal admission. Admission uses actual profiles and 20% wall-time reserve. No cumulative GPU-hour cap. Seven-day wall and six-day online deadlines, per-worker 22h deadline and 64GiB output limit are recoverable engineering protections, not scientific stopping criteria. Failures and original T0/cost remain in the ledger; no performance-based retry or pruning.
