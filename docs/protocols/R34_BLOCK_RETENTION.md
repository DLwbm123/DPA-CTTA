# R34: sparse block-retention action value

## Authority and question

The user authorized experiments following the reviewed priority: first establish the future value of a concrete sparse action, then consider observability and a policy, and only later assess whether RL is necessary. R30 already found only +0.009 pp of H64 oracle gain for one-step strength actions on sampled ANCHOR states. R33 found that swapping matched-age Adam donors does not eliminate REFUGE_Valid's retained-update loss. R34 therefore tests one different, stage-level action on native C, not another strength, donor or source-reset sweep.

At a fixed arrival count, retain the latest 32 updates or restore the complete learning state from before those 32 updates. Both actions use exactly the same native post-update predictions throughout that already processed block. The only intervention is the state retained for future arrivals. This is a local counterfactual diagnostic on native-C-reachable states, not a deployed policy or an RL experiment.

## Frozen actions, positions and future rule

Use the unchanged source checkpoint, native C (current-image BN; BN affine Adam LR1e-4), preprocessing, 1,951-arrival streams, seeds 20260907/17011/29009 and the two original orders. No source training images, new data, domains-as-input, objective change or parameter search.

Block length K=32. Decision points t=64+128j, j=0..14, in each stream. The shared block is t-31..t. These are integer arrival positions; true domain boundaries never trigger a decision. KEEP retains state s_t. ROLLBACK restores parameters, gradients, buffers, optimizer moments/local step and other persistent learning fields from s_(t-32), while preserving the consumed arrival position t and exogenous random stream at t. It does not reset to the source checkpoint. Restoring the local Adam clock is part of this coherent rollback action, not an attempt to isolate moment content from optimizer age. Physical costs never roll back.

Thereafter both branches apply unchanged native C once per future image, retaining their own subsequent state. At each corresponding future arrival, native augmentation RNG input/output must match the baseline schedule. Do not rewind the image sequence, skip the future updates, restore the baseline at each step, or use future inputs for a decision. KEEP future predictions are reused from the same newly replayed native trajectory; the replay must exactly match R30 C_CONT masks. The processed block's outputs are shared by construction, not separately selected.

Primary horizon H=256 future arrivals, excluding the shared block. H=64 is the sole auxiliary horizon. Run min(256,1951-t) future arrivals for every point. There are 13 fully eligible H256 and 15 fully eligible H64 points per job. The two tail points have 223 and 95 available future arrivals and remain in the output/eligibility ledger; do not wrap, replace or silently pad them. Windows may cross domain boundaries and overlap one another. Publish origin-domain and future-domain composition and eligible role counts from manifests before launch. In particular, H256 origin-domain coverage is incomplete near the stream end; do not call this a balanced four-domain endpoint.

Six jobs contain 90 paired decisions (180 evaluated action paths, with KEEP reused), 78 primary H256 pairs and 90 H64 pairs. Each job performs 1,951 native replay updates plus 3,646 rollback-future updates =5,597 Adam/backward calls and 44,776 model forwards. Formal totals are 33,582 updates and 268,656 forwards. No extra pre-readout is needed. Six concurrently run profiles, two per GPU, each perform 72 replay arrivals and one 8-arrival rollback future =80 updates/640 forwards. Profile total480 updates/3,840 forwards is additional cost and supplies engineering timing only.

## Scoring and allocation gates

SEARCH is primary; already-exposed legacy REVIEW is separately descriptive. Context is processed but never assigned a score or included in denominators. For each eligible point/horizon/role, score the exact same future contents for both actions, average Dice equally over OD/OC and eligible images, and retain channel cells. A window with no eligible contents has no score. The outer primary mean averages eligible windows within each seed/order, then equally weights all six seed/order groups. It is not an image-weighted full-stream or balanced-domain efficacy estimate.

Report KEEP and ROLLBACK, ROLLBACK-KEEP, and a label-informed window oracle that chooses one complete action for the whole window based on its joint OD/OC mean; ties choose KEEP. Never choose per future image or per channel. Report oracle-KEEP and oracle-best-fixed-action, with the stronger single fixed action defined on the same registered endpoint. Also report per-order oracle-best-fixed-within-order, six group effects, all negative window/channel/stratum cells and cumulative paired differences separately from means. Channel effects of the oracle must use the same jointly selected action. No confidence claim treats overlapping windows or repeated contents/seeds as independent patients.

At H256 SEARCH only, fixed ROLLBACK warrants a separate full-policy check if its mean gain is >=0.3pp, both order means improve and >=5/6 group means improve. Conditional action headroom warrants a subsequent observability experiment if oracle-best-fixed >=0.3pp and oracle-best-fixed-within-order >=0.15pp in each order. These are declared resource-allocation thresholds, not significance or clinical thresholds. An oracle passes no deployability gate. If neither condition holds, stop this registered K32/native-C/position-grid action rather than scan lengths or train RL. If a condition holds, freeze the next experiment before execution; do not silently fit a selector or switch the primary horizon.

R34 does not establish that a policy visiting its own states will improve, that an online observable predicts action value, or that RL is necessary. Unknown patient linkage/ROI provenance and development-exposed data remain limitations.
