# Authorized concurrency amendment

The user explicitly authorized replacement of scheduling controls while preserving the three existing compute processes. The six already registered jobs may run concurrently, two on each of physical GPUs 0, 1 and 2. The scientific code, resolved configuration, matrix, original T0, deadlines, data access rules and cost accounting remain unchanged. No new profile, seed, arm or retry is added. The original single-worker profile ETA is no longer a measured concurrency estimate.

The original supervisor is paused before admitting the queued jobs. Its existing compute children continue normally. A replacement supervisor runs the three queued jobs under separate per-job GPU-slot leases. After all compute processes finish, it interrupts and resumes the original supervisor solely to reap its original children and preserve their actual exit codes. The old supervisor's expected cancellation state is archived as `LEGACY_CONTROL_RETIREMENT.json`, not interpreted as an experimental failure. The replacement then requires all six successful receipts and inactive process records with exit code zero before CPU scoring. Both watchdogs retain the original absolute deadline; the original watchdog retires after its supervisor exits.

A CPU-only integration check used three real child processes: all completed while their parent was stopped, and the resumed parent reaped all three with exit code zero. A stale PID identity was rejected. Scientific GPU computations were not rerun for this scheduling change. Sharing GPUs may reduce individual worker throughput; aggregate speedup remains unmeasured at admission.
